Architecture

The Full Data Pipeline

Two systems, two formats, zero shared schema out of the box. The pipeline was designed so every downstream step inherits structure from the one before it — not the other way around.

01
MATLAB

Automated ingestion of SN and ADO CSVs, date validation, null removal, string normalization, cross-system ID mapping, and SLA aging computation

02
MySQL Workbench

Enriched tables loaded into a relational schema with foreign keys linking SN ticket numbers to ADO enhancement IDs — schema defined once, enforced at the DB layer

03
Power Query

Power BI connects via the SQL Server connector and inherits column types and joins automatically — no manual field remapping on every refresh

04
Power BI

Two dashboards on a clean data model — Customer view for external stakeholders and Internal view for tracking delivery efficiency across teams

// Why route through SQL at all

MATLAB exports clean CSVs but Power BI has no way to know what the columns mean — every refresh would require manually re-specifying types, joins, and relationships inside Power Query. That breaks under team use and doesn't scale to new data sources.

Pushing to MySQL first means the schema lives at the database layer, not inside a BI tool. Power BI connects once and inherits everything. It also means any analyst can write queries directly against the same data independently of the dashboard — the database is the source of truth, not the visualization.

Exploratory Data Analysis

Pre-Dashboard Analysis in MATLAB

The EDA phase wasn't cosmetic. Each analysis below directly shaped a decision in the final dashboard design — the workload imbalance finding drove the assignee filter, the aging distribution drove the SLA highlight in the completion chart, and the traceability check determined what data was even safe to use.

Enhancement State Distribution
56.9% closed is a healthy signal, but 19.4% still active and 12.5% new means roughly 1 in 3 tickets is unresolved at any snapshot. The "Awaiting Customer" slice — small but persistent — flags a process gap where tickets stall waiting on client input with no automated escalation.
Workload by ADO Assignee
Anthony carries nearly 2x Jane Doe's load and ~3.5x Harry's. This kind of skew doesn't show up in ticket counts alone — it only becomes visible when you aggregate by assignee and sort. This finding directly drove the assignee slicer in the internal dashboard.
Open Ticket Aging — SLA Risk Analysis
Right-skewed distribution with a long tail past 84 days (red). Bi-weekly bins were chosen to match a reasonable sprint-length resolution window. Tickets in the 98+ day bucket are almost certainly SLA violations and represent operational risk that wasn't being tracked before this pipeline existed.
SN to ADO Cross-System Traceability
78% of ServiceNow tickets could be matched to an ADO enhancement record by ID. The 22% gap wasn't silently dropped — it was flagged, documented in the MATLAB quality report, and excluded from the SQL schema load. Data integrity audit, not just cleaning.
Monthly Enhancement Volume — Temporal Demand Pattern
Mid-year spike (June–August, highlighted) aligns with DEN's peak air traffic season — operational pressure on the airport translates directly into increased IT enhancement demand. This seasonal pattern is the kind of insight that drives quarterly staffing and backlog planning, and it was invisible before the datasets were merged.

Output

Power BI Dashboards

Both dashboards were built on the SQL schema — not on raw CSVs. The distinction matters: schema-backed dashboards don't break on refresh and support multi-user querying outside Power BI.

01 — Internal View
Company's Perspective
Tracks enhancement states, assignee workloads, completion % by enhancement ID, and customer SN distribution. Sliceable by ADO assignee.
02 — Customer View
Client's Perspective
Surfaces feature request progress, user story completion rates, and enhancement state breakdowns — designed for external stakeholder consumption, not internal ops.
Workload Imbalance Anthony's load is nearly 2x the next assignee. Invisible in raw data, obvious in aggregate. The dashboard makes it a one-glance finding for any manager.
Backlog Health 56.9% closed is good. But 32% active+new means the team is absorbing new work faster than it's clearing the queue — a capacity signal worth monitoring.
Customer Prioritization Tracy Chapman holds ~20 assigned SN tickets — nearly 3x the next customer. Cross-system merge made this visible for the first time.
Awaiting Customer Gap A persistent "Awaiting Customer" state means tickets stalling on client input with no escalation path. A process gap the data exposed, not assumed.
